Buenas Prácticas de Calidad del Software

El proyecto SIS-FP aplica estándares internacionales de calidad, asegurando confiabilidad, rendimiento y seguridad en cada módulo. Su enfoque combina metodologías tradicionales y ágiles para garantizar la mejora continua.

Ver Repositorio en GitHub

Instrumentos de Calidad de Software

Lista de Verificación

Valida el cumplimiento de los requerimientos funcionales y no funcionales definidos para cada módulo.

Registro de Pruebas

Documenta resultados de pruebas unitarias, integradas y de aceptación realizadas con Insomnia y Postman.

Control de Versiones

Se utiliza Git y GitHub para la trazabilidad de los cambios, revisión de commits y control de incidencias.

Métricas de Rendimiento

Evalúa tiempos de respuesta, eficiencia de la API y consistencia de datos en MongoDB.

Documentación Técnica

El README del repositorio centraliza guías de instalación, arquitectura y configuraciones.

Validación de Seguridad

Autenticación JWT, hash de contraseñas y validación de entradas para evitar inyecciones.

Calidad Mínima Aceptable

Categoría Requisito Cumplimiento
Funcionalidad CRUD completo para todas las entidades principales. ✅
Seguridad JWT, hash bcryptjs y middleware de autenticación. ✅
Interfaz Diseño responsivo con Tailwind CSS y validaciones de formularios. ✅
Rendimiento Respuestas inferiores a 2 segundos en operaciones CRUD. ✅
Documentación Manual técnico, README y guías de instalación. ✅

Pruebas Realizadas

Pruebas Unitarias

Validación de endpoints del backend con Insomnia y Postman.

Pruebas de Integración

Verificación de la comunicación entre el frontend y el backend mediante peticiones HTTP.

Pruebas Funcionales

Evaluación de formularios y operaciones CRUD en el frontend con validaciones completas.

Pruebas de Seguridad

Evaluación de autenticación, validación de tokens y control de accesos no autorizados.

Metodologías de Desarrollo

Cascada (Tradicional)

Aplicada en la fase de análisis y diseño inicial del sistema y base de datos.

Scrum (Ágil)

Desarrollo iterativo por sprints, priorizando entregas funcionales y retroalimentación continua.

Kanban (Ágil)

Uso de tableros visuales en GitHub Projects para el seguimiento de tareas y avances.

Pruebas Continuas

Validación constante en cada sprint mediante pruebas unitarias y revisiones de código.
